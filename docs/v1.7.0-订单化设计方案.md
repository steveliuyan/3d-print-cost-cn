## 0. 一句话结论

把"一次算一个东西"升级为"**一张订单 = 多个行项（设备×材料×数量）**"，
再加**阶梯定价**与**报价单抬头（编号/客户/有效期/状态）**，
同时把已在用的 `dpc_quotes_v1` 单条快照**无损迁移**成订单结构，旧数据一条不丢。

**核心手法：不重写计算逻辑，而是把 `compute()` 里"从 DOM 读参数"这一步剥出来** ——
改成从普通对象 `fields` 读。单件页面变成"1 行的订单"，多品项就是"N 行"。回归风险最低。

## 2. 数据结构设计

### 2.1 新的存储键

```
QKEY 旧: dpc_quotes_v1   （单条快照数组）
QKEY 新: dpc_orders_v1   （订单对象数组）
```

> 保留旧键**不删**，仅作迁移来源；迁移成功后写新键，旧键留作回滚兜底（首版不清理）。

### 2.2 订单对象（Order）

```jsonc
{
  "id": "ord_1759..._a3f",     // 订单主键（时间戳+随机后缀）
  "no": "DPC-20261012-001",    // 报价单编号（可编辑，默认按日流水）
  "t": 1759...,                // 创建时间（毫秒）
  "updatedAt": 1759...,        // 最近修改时间
  "status": "draft",           // draft | quoted | accepted | archived
  "customer": {                // 抬头（可空）
    "name": "",
    "contact": "",             // 电话/微信/邮箱
    "note": ""
  },
  "validUntil": "2026-11-11",  // 报价有效期（可空）
  "currency": "CNY",
  "lines": [ Line, ... ],      // 行项（见 2.3），至少 1 条
  "orderLevel": {              // 订单级参数（不随行项变）
    "bulkDisc": 0,             // 兼容旧字段：整单统一折扣 %
    "shipping": 0,             // 整单运费
    "commission": 5,           // 平台佣金 %
    "markup": 2.5              // 加价倍率（订单级默认，可被行项覆盖）
  },
  "tiers": [ Tier, ... ],      // 阶梯定价规则（见 2.4，可选）
  "totals": {                  // 冗余缓存（迁移/展示用；真值仍由引擎算）
    "totalCost": 0, "revenue": 0, "profit": 0, "margin": 0, "unitAvg": 0
  }
}
```

### 2.3 行项（Line）

```jsonc
{
  "id": "ln_1759..._b7c",
  "devName": "Bambu A1",       // 展示名（设备预设名或"自定义设备"）
  "matName": "PLA 基础",
  "qty": 1,                    // 本行件数
  "fields": {                  // 完整参数快照（复用现有 18 字段）
    "qty":"1","printHours":"3","grams":"55","spoolPrice":"65","waste":"5",
    "printerPrice":"2199","lifeHours":"5000","maintPerHour":"0.28",
    "power":"200","elecPrice":"0.6","laborRate":"30","laborMin":"5",
    "postCost":"1","failRate":"8","markup":"2.5","commission":"5",
    "shipping":"0","bulkDisc":"0"
  }
}
```

> **关键复用**：`fields` 的键与现有 `fieldSnapshot()` 完全一致 → `histClick` 回填逻辑可原样搬进"载入订单行"。

### 2.4 阶梯定价（Tier）

```jsonc
{ "minQty": 1,  "disc": 0  }
{ "minQty": 10, "disc": 5  }   // ≥10 件 5% off
{ "minQty": 50, "disc": 12 }   // ≥50 件 12% off
```

**规则**：取该行 `qty` 命中的**最大 minQty** 对应的 disc；与订单级 `bulkDisc` **取较大者**（不叠加，避免双重打折失真）。
命中逻辑：`qty >= minQty` 的最大一段。

## 3. 计算引擎改造（最小侵入）

### 3.1 现状 → 目标

```js
// 现状（1273）：从 DOM 读
function compute(){ var qty = num("qty"); ... }

// 目标 A：参数化（纯函数，可单测）
function computeFrom(f){ /* 内部逻辑与现 compute 完全相同，只是 num("x") → nf(f,"x") */ }

// 目标 B：订单聚合
function computeOrder(order){
  var lines = order.lines.map(function(ln){
    var r = computeFrom(mergeOrderLevel(ln.fields, order.orderLevel));
    r.disc = tierDisc(order, r.qty);
    r.revenue = r.sellNet * r.qty * (1 - r.disc);
    r.profit  = r.revenue - r.totalCost;
    return { line: ln, r: r };
  });
  // 订单级：运费只算一次（放订单级 totalCost）
  ...
}

// 兼容层（保住单件页面 + 旧测试）
function compute(){ return computeFrom(fieldSnapshot()); }
```

- `computeFrom` = 纯函数，无 DOM 依赖 → jsdom 可直接断言。
- `compute()` 保留为薄封装 → **现有 245 条断言中凡是调 `compute()` 语义的全部不用改**。
- `mergeOrderLevel`：订单级 markup/commission/shipping/bulkDisc 覆盖行项同名字段（行项留空则用订单级）；保证"单件页面 = 1 行订单 + 订单级参数"行为与今天逐字节一致。

### 3.2 聚合口径（务必在测试里钉死）

| 指标 | 口径 |
|---|---|
| 订单总成本 | Σ 各行 `totalCost` + 订单级 `shipping`（运费**不**按行重复计） |
| 订单总收入 | Σ 各行 `revenue`（各行已含自身折扣） |
| 订单总利润 | 总收入 − 总成本 |
| 毛利率 | 总利润 / 总收入 |
| 平均单件成本 | 总成本 / Σqty |

> 迁移验收基准：旧单条快照迁移成 1 行订单后，`computeOrder` 输出的
> `revenue / totalCost / profit` 必须与旧快照里存的三个数**分毫不差**（浮点 `toFixed(2)` 比对）。

## 4. 数据迁移方案（`dpc_quotes_v1` → `dpc_orders_v1`）

**触发时机**：应用启动初始化时，`if(!localStorage.getItem("dpc_orders_v1") && loadQuotes().length)` 执行一次。

```
旧一条 = { t, dev, mat, qty, disc, unitCost, sellNet, revenue, totalCost, profit, fields }
        ↓ 映射
新一单 = {
  id, no: "DPC-<日期>-<序号>",
  t: 旧.t, updatedAt: 旧.t,
  status: "quoted",
  customer: null,
  validUntil: null,
  lines: [ { id, devName: 旧.dev, matName: 旧.mat, qty: 旧.qty, fields: 旧.fields } ],
  orderLevel: { bulkDisc: 旧.disc*100, shipping: fields.shipping, commission: fields.commission, markup: fields.markup },
  tiers: [],
  totals: { totalCost: 旧.totalCost, revenue: 旧.revenue, profit: 旧.profit, margin: ..., unitAvg: 旧.unitCost }
}
```

要点：
- **幂等**：迁移只在 `dpc_orders_v1` 不存在时跑；跑完写入版本哨兵 `dpc_orders_migrated = "1"`。
- **不删旧键**（回滚兜底）。
- **编号连续**：按 `t` 升序生成日流水，保证历史顺序不乱。
- **降级安全**：解析失败 → 保持旧数据不动、不写新键、控制台 warn（不弹窗打扰）。

### 5.2 交互细节
- "添加行项"：默认把**当前单件页参数**快照成一行 → 零学习成本。
- 行项"编辑"：弹回单件页（带"正在编辑订单第 N 行"提示），改完"应用"
  写回该行 `fields`。
- 报价历史面板升级为**订单列表**：显示编号/客户/状态/金额/日期，`载入 / 复制为新单 / 删除 / 归档`。
- 状态徽标配色（中国习惯）：`draft` 灰 / `quoted` 蓝 / `accepted` 绿 / `archived` 灰删除线。

### 5.3 不做什么（防止范围蔓延）
- ❌ 不做客户 CRM（只存抬头字段，不建客户库）。
- ❌ 不做多币种（`currency` 字段先占位，恒 CNY）。
- ❌ 不做云同步 / 多设备。
- ❌ 不改单件页现有视觉与计算口径。

## 6. 导出改造

| 出口 | 单行项时 | 多行项时 |

| 打印 `renderPrintPage` | 与今天完全一致（保持回归） | 增"行项明细表"（设备/材料/数量/单件成本/小计），再跟汇总 |

## 10. 分期与风险

**分期建议（每期一个可交付、可回归的提交）**
1. **P1 引擎解耦**：`computeFrom` + `compute()` 兼容层 + A1。（无 UI 变化，绿色后即安全）
2. **P2 订单模型 + 迁移**：`computeOrder` / `loadOrders` / `migrateQuotes` + A2–A5。
3. **P3 订单 UI**：分段控件、行项列表、抬头、汇总 + A6。
4. **P4 出口**：打印/长图/CSV 多行 + A7。
5. **P5 备份 + 版本**：备份含订单、四处版本号、A8–A9 → 打包发版。

**风险**
| 风险 | 等级 | 缓解 |
|---|---|---|
| `compute()` 语义漂移导致旧断言误报 | 中 | A1 钉死：同参数下 `computeFrom(fieldSnapshot())===compute()` |
| 迁移把用户历史算错 | 高 | A4 逐项 toFixed(2) 比对 + 不删旧键 + 备份先行 |
| jsdom 浮点尾差 | 低 | 一律 `toFixed(2)` 比较，不比原始浮点 |
| 多行项导出高度/分页 | 中 | 单行项走旧路径；多行项单独测 |
| 订单膨胀超 localStorage 上限 | 低 | 订单上限 60（比旧 100 保守，单条更大）；`slice` 截断 + 提示 |
